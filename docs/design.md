## 1. 项目概述

### 1.1 目标

为《原神》玩家提供月谕圣牌的**交换撮合**服务：玩家告诉网站「我有什么多余的、我缺什么」，网站帮他找到正好能互换的人，然后双方在游戏内加好友完成交换。

**网站只做信息匹配，不经手任何游戏内物品。**

### 1.2 设计原则

| 原则 | 说明 |
|---|---|
| 移动端优先 | 先按 360–430px 宽度设计，PC 是同一套布局的放宽版，不另做一套。 |
| 3 步以内上手 | 首次进入：填 UID → 选牌 → 发布。不注册、不登录。 |
| 一屏只做一件事 | 每个页面只有一个主按钮，次要操作收进底部抽屉或菜单。 |
| 卡牌即界面 | 卡面插画就是主要视觉元素，尽量少用文字和图标。 |
| 好看但不卡 | 特效分三档（见第 8 节），低端机自动降级，任何档位功能都完整。 |
| 本地优先 | Box 数据存在浏览器本地，不联网也能管理；B站用户额外同步到 B站云存储；只有发布换牌需求时才把数据传给后端。 |
| 一套代码，两处部署 | 同时托管在 B站 Toy 和独立静态站（如 Vercel）；SDK 能力按环境检测，缺少能力时有替代方案，界面不会因此缺页或报错。 |

### 1.3 范围

**v1 包含**：Box 管理（快速 / 完整两种模式）、UID → 服务器识别、UID 脱敏与按需展示、实时 1 对 1 匹配、交换结果确认、信用与限频、中英双语；B站 Toy 部署（B站用户与匿名用户两类身份）和独立站部署，两者都是 PWA。

**v1 不包含**：截图识别导入（另有详细要求，后续单独设计，见第 10 节）、自建的注册登录体系（只有「B站身份」和「匿名身份」两种）、站内聊天、排行榜等游戏化功能、单向赠送、三人及以上的环形交换（预留扩展点）、社区和广场功能。

### 1.4 目标用户与典型场景

- **小A（重复牌很多）**：有 5 张「星」，还缺「塔」。在完整 Box 里录入数量，一键发布，等待匹配。
- **小B（只想换一张）**：不想整理 Box，直接选「我给愚者，我要太阳」，点发布。
- **小C（B站用户，PC + 手机）**：在 B站 网页端打开 Toy 整理 Box；之后在 B站 App 里打开同一个 Toy，Box 和匹配状态已经自动同步。
- **小D（匿名用户）**：从群里拿到 Vercel 链接直接使用；换手机时复制 Box 字母码导入收藏数据，新设备使用独立匿名身份。

## 2. 核心概念与规则

### 2.1 术语

| 术语 | 含义 |
|---|---|
| 圣牌（Card） | 22 种月谕圣牌之一，用 `id` 1–22 标识。 |
| Box | 玩家每种圣牌的持有数量。 |
| 保留数（Keep） | 每种牌自己留着的张数，默认为 1。 |
| 可换（Spare） | `max(持有 - 保留, 0)`，可以拿出去换的张数。 |
| 缺少（Missing） | 持有数为 0 的牌，默认就是「想要」的牌。 |
| 换牌需求（Listing） | 发布到匹配池里的一条需求：给出（give，带数量）和想要（want）。 |
| 匹配（Match） | 两个换牌需求之间配成的一组交换，包含 1 对或多对「你给 X ⇄ 你得 Y」。 |
| 分区（Region） | 能互相加好友的服务器集合，匹配只在同一分区内进行。 |
| 账号（Account） | 本站的交换身份，分为 `bili`（B站用户）和 `anon`（匿名用户）两类，见第 3 节。每个账号保存 1 个当前原神 UID，不同账号可填写相同 UID。 |
| 原神 UID | 用户填写的游戏匹配与加好友信息，用于识别服务器和分区；不验证归属，不作为交换账号标识。 |
| 运行环境（Env） | `toy-app` / `toy-web` / `standalone`，决定哪些 SDK 能力可用，见 3.1。 |

**文案约定**：需求统一称为「换牌需求」，发起按钮使用「帮我找人换牌」；已找到伙伴但尚未完成的交换展示为「待完成的交换」。

### 2.3 Box 规则

- 每种牌的数量范围是 0–99，超出时提示「数量异常」。
- 「保留数」默认是 1，可以在设置里改成全局 0、1 或 2，也可以在单张牌上单独设置（高级选项）。
- 自动计算以下数据：
  - **收藏进度** = 持有数 ≥ 1 的种类数 / 22
  - **缺少** = 持有数为 0 的牌
  - **可换** = 每种牌的 `持有 - 保留` 之和
- 「想要」默认等于「缺少」，用户可以手动去掉某张。已经拥有的牌不能加入「想要」（没有「多收一张」的场景）。

### 2.4 交换规则（已确认）

- **严格 1 张换 1 张**：A 给 B 一张 X，B 给 A 一张 Y。
- 交换双方需要先在游戏内互加好友；跨服务器不能加好友。原神的好友申请可以附带留言。
- 一次匹配可以包含多对交换（比如 A 给 B「星」和「月亮」，B 给 A「塔」和「太阳」）。
- **主动方上限 3 对**：发布换牌需求或重新匹配时，系统会立即替本人扫描匹配池，这一次**最多匹配 3 对交换**。
- **被动方不限**：换牌需求留在池中等待时，被其他人匹配到的次数和总张数**不受限制**（每一次仍受对方的 3 对上限约束，所以每个匹配最多 3 对）。
- 不提供单向赠送。

### 2.5 UID → 服务器

前端实时识别（输入即显示结果），后端以同一份规则再校验一次。静态规则保存在本地模块并随前端打包，不通过 `/config` 下发。

| UID 形式 | 判定 | 服务器 | 分区 |
|---|---|---|---|
| 9 位，首位 1 / 2 / 3 | 国服官服 | 天空岛 | `cn` |
| 9 位，首位 5 | 国服渠道服 | 世界树 | `cn` |
| 9 位，首位 6 | 美服 | America | `us` |
| 9 位，首位 7 | 欧服 | Europe | `eu` |
| 9 位，首位 8 | 亚服 | Asia | `asia` |
| 9 位，首位 9 | 港澳台服 | TW/HK/MO | `tw` |
| 10 位，前缀 `18` | 亚服 | Asia | `asia` |
| 其他 10 位前缀 | 按规则表判定；没命中就提示「无法识别服务器，请检查 UID」，不能继续 | — | — |

- 国服官服（天空岛）与渠道服（世界树）数据互通，合并为同一个分区 `cn`；除此之外，跨服务器不能互加好友，因此不能互相匹配。
- 格式校验：只能是纯数字，长度 9 或 10，且不能是全相同数字或明显的顺序串（比如 `123456789`）。

## 3. 运行环境与用户类型（B站 Toy / 独立部署）

> 参考：`docs/toy-js-sdk-abilities.md`（Toy JS SDK 能力清单，2026-09-18 版）

同一套代码构建出两种部署包：

- **Toy 包**：托管在 B站 Toy 平台，地址为 `https://www.bilibili.com/toy/<slug>/`。
- **Web 包**：部署在 Vercel 等普通静态服务器上。

两个包共用同一个后端和同一个匹配池。

### 3.1 三种运行环境

| 环境 | 判定 | 典型入口 | SDK |
|---|---|---|---|
| `toy-app` | Toy 包，且 `toy.isSupport('closeBrowser')` 为 true | B站 App 内打开 Toy | 全部能力 |
| `toy-web` | Toy 包，在浏览器中打开（`closeBrowser` 不可用） | 电脑或手机浏览器访问 bilibili.com/toy/… | 无容器、分享、保存相册能力 |
| `standalone` | Web 包，或页面上不存在 `window.toy` | Vercel 域名 | 无 |

判定逻辑集中在 `src/platform/` 中（见 12.5）。业务代码只调用平台适配层的方法，**不直接使用 `window.toy`**。

### 3.2 两类用户

| | **B站用户**（`bili`） | **匿名用户**（`anon`） |
|---|---|---|
| 成为条件 | 在 Toy 环境中，且已登录 B站（云存储可读写） | 其他所有情况：独立部署、Toy 中未登录、云存储不可用 |
| 身份凭证 | 账号密钥保存在 **B站云存储**中（随 B站账号走），换取 CloudBase 自定义登录会话 | CloudBase 匿名会话，由 SDK 保存在当前设备 |
| 跨设备 | **自动**：在任意设备用同一 B站账号打开 Toy 即可恢复 | Box 字母码导出 / 导入；身份与交换记录仍属于原设备 |
| Box 存储 | 本地 + 云存储自动同步，可导出 Box 字母码 | 仅本地，可导出 Box 字母码 |
| 头像与昵称 | 可以使用 B站头像和昵称（需用户授权，可拒绝） | 系统生成：月相头像 + 「旅人·A3F9」 |
| 给对方的留言 | 保留原有中文快捷留言，新增固定换牌时段，可选单选；不支持自定义文本 | 相同，前后端统一限制为预设 |
| 查看对方 UID 前 | **需要关注 UP主**（用 `getAuthorRelation` 检查，见 5.5） | 不需要（无法检查） |
| 分享 / 保存图片 | App 内使用原生分享面板和相册；浏览器中使用复制链接和下载 | 使用 Web Share API、复制链接和下载 |
| 匹配规则、信用、每日次数 | **完全相同** | **完全相同** |

**为什么匹配权益不做区分**：

- SDK 不向页面提供 B站 UID，`toyOpenId` 也明确「不是鉴权凭证」；后端没有校验「这个人确实是 B站用户」的服务端接口，任何人都可以在客户端伪造 B站身份。所以 B站用户只能获得**便利性权益**，不能获得**匹配特权**。
- 信用分记录在**交换账号**上（见 11.5），与账号类型无关；填写相同原神 UID 的其他账号不共享信用或处罚。
- 平台已确认**不会提供**服务端校验身份的接口，所以这个设计是长期方案，不是过渡方案。

### 3.3 B站用户身份流程

```
页面启动（Toy 环境）
  │
  ├─ toy.getCloudStorage(['cred'])            ← 只要求已登录，不弹授权窗
  │     ├─ 307044 限流 → 退避重试（见 3.6）
  │     ├─ 其他任何错误 → 视为「未登录或不可用」，按匿名用户处理，
  │     │                界面提示「登录 B站 可跨设备同步」；下次启动时再试
  │     ├─ 有 cred → POST /session { provider:'bili', credential }
  │     │            → 拿到 CloudBase 自定义登录 ticket，由 SDK 建立会话
  │     └─ 没有 cred → POST /session { provider:'bili' }
  │                  → 后端新建 bili 账号，返回 { ticket, credential }，由 SDK 建立会话
  │                  → toy.setCloudStorage({ cred })
  │                    （写入失败时重试一次；仍然失败就降级为匿名用户并提示）
  │
  └─ 用户在 UI 中点击头像位置（用户手势）→ toy.getUserProfile()
        ├─ 用户同意 → 拿到 avatar / nickname / toyOpenId
        │            → PUT /me { toyOpenId }
        │              后端保存 HMAC(toyOpenId)，用于「一个 B站账号对应一个交换身份」的去重
        └─ 用户拒绝 → 继续以 B站用户身份使用，只是不显示 B站头像和昵称
```

要点：

- **身份认证靠云存储里的密钥**。云存储按「B站登录用户 + 本 Toy」隔离，所以只有该用户本人能读到这个密钥。这一步不弹授权窗，打开页面就能完成。
- 未登录时云存储返回的具体错误类型目前**不明确**，所以不依赖错误码来判断，统一采用上面的「非限流错误都按未登录处理」策略。这样即使判断错了，用户也只是暂时以匿名身份使用，不会出现功能缺失。
- 本 Toy **开启 OpenID 模式**，`getUserProfile` 会返回 `toyOpenId`。
- **只在用户主动点击时调用 `getUserProfile`**。首次调用会出现平台固定的授权弹窗，所以不放在首屏自动调用。引导页的「开始交换」按钮下方提供一个可选入口：「使用 B站头像昵称」。
- **`toyOpenId` 只用于去重**：后端只保存 `HMAC(serverKey, toyOpenId)`，原文**不落库、不写日志、不埋点**（遵守 SDK 的数据使用限制）。它不能单独用于登录。
- 如果用户清空了云存储导致 `cred` 丢失，但 `toyOpenId` 的哈希能对应到已有账号，界面提示身份关联冲突并提供反馈入口。不能只凭 `toyOpenId` 自动登录。

### 3.4 匿名用户身份流程

```
页面启动 → CloudBase SDK 中有有效匿名会话？
    ├─ 有 → 复用会话
    └─ 没有 → 等到首次「帮我找人换牌」时才通过 SDK 匿名登录
              → 获得 CloudBase 会话，业务身份为 anon
              → 发布换牌需求后直接进入交换页
```

- 匿名用户在发布换牌需求之前**不需要联网建号**：浏览和编辑 Box 都在本地完成。
- 匿名身份仅在当前设备保存。收藏数据可通过「我的」页面的 Box 字母码导出 / 导入，不迁移身份、换牌需求或交换记录。

### 3.5 账号之间的关联

| 场景 | 处理 |
|---|---|
| 匿名用户之后在 B站 App 里打开 Toy | 使用 B站身份；可通过 Box 字母码导入收藏数据，不提供账号合并 |
| B站用户想在 Vercel 站点或其他浏览器上使用 | 独立站使用本设备匿名身份，可通过 Box 字母码导入收藏数据；B站身份仅通过 Toy 云存储中的密钥跨设备使用 |
| 不同账号填写同一原神 UID | 正常保存，各自发布需求并匹配；不提示重复、不合并账号、不要求关联或验证归属 |

Toy 与独立站共用匹配池。不同账号即使填写相同 UID，需求、Box、交换记录、次数和信用仍各自独立；仅同一交换账号在不同设备上的使用共享账号状态。客户端不显示 UID 重复标记或关联引导。

### 3.6 SDK 能力使用一览

| 能力 | 用在哪里 | 环境 | 不可用时的替代方案 |
|---|---|---|---|
| `getCloudStorage` / `setCloudStorage` / `removeCloudStorage` | 身份密钥、Box 同步、偏好设置 | toy-app、toy-web（需登录） | localStorage |
| `getUserProfile` | 头像和昵称（可选）、toyOpenId 去重 | toy-app、toy-web | 系统生成的头像 |
| `checkInputSafety` | 申诉说明 | toy-app、toy-web | 换牌留言统一使用快捷短语或固定时段预设，无需文本检测 |
| `share` | 等待页的「邀请朋友来换牌」（匹配池里的人越多，越容易配上） | 仅 toy-app | `navigator.share` → 复制链接 |
| `getQrCode` | 电脑端「扫码到手机继续」 | toy-app、toy-web | 独立站内置轻量二维码库（只编码站点链接，不包含身份凭据） |
| `saveImageToAlbum` | 保存交换名片 | 仅 toy-app | `<a download>` |
| `onContainerChange` / `getContainerState` | 读取安全区和视口，用于底部标签栏和抽屉的避让 | 仅 toy-app | CSS `env(safe-area-inset-*)` |
| `setContainerMode` | 不使用（保持竖屏、非沉浸，避免和 App 自身导航冲突） | — | — |
| `getAuthorRelation` | 查看 UID 前检查是否已关注 UP主（`isFollowing`） | toy-app、toy-web（外部手机浏览器返回 unsupported） | 不拦截，直接显示 |
| `getAuthorProfile` | 关注引导抽屉中显示 UP主 头像、昵称和粉丝数 | toy-app、toy-web | 只显示文字 |
| `navigate` | 「去关注」跳转到 UP主 空间（`type: 'space'`） | toy-app、toy-web | 普通外链 |
| `submitScore` / `getRankList` / `getMyRank` | **不使用**（不做排行榜） | — | — |
| `closeBrowser` | 不主动使用 | — | — |
| `requestCamera` | v1 不使用（以后可以做「对准屏幕拍照识别」） | — | — |

SDK 调用约束（按照平台的最佳实践）：

- 每次调用前先用 `isSupport` 检查；所有错误统一包装成 `PlatformError`，界面只显示友好的提示文案。
- 云存储写入**做防抖**：编辑后 5 秒合并成一次写入，页面切到后台（`visibilitychange`）时立即写入；每次只调用一次 `setCloudStorage` 批量写入，不按 key 循环。
- 遇到 `307044` 限流时，按 2s → 4s → 8s 指数退避重试，最多 3 次；仍然失败就保留本地数据，在下次进入页面时再同步。
- 关注状态只在用户点击「开始交换」时查询，以及从 UP主 空间返回页面时再查一次，不做定时轮询。

### 3.7 云存储键规划

每个 Toy 最多 128 个 key，单个 value ≤ 1024 字节。本项目实际只使用 5 个 key：

| key | 内容 | 示例 / 大小 |
|---|---|---|
| `cred` | 后端签发的账号密钥 | 约 44 字符 |
| `box` | `v1\|<22 个数量，逗号分隔>\|<保留数>` | `v1\|3,1,0,…\|1`，约 70 字节 |
| `quick` | 快速模式的选择：`give=17:2,18:1;want=16,19` | < 200 字节 |
| `prefs` | 语言、特效档位、是否开启通知等（JSON） | < 200 字节 |
| `sync` | `{ "box": updatedAt, "quick": updatedAt }`，用于解决冲突 | < 100 字节 |

**冲突处理**：启动时比较本地和云端的 `updatedAt`，较新的一方覆盖较旧的一方。如果两边都在上次同步之后被修改过（比如两台设备都离线编辑过），弹出「使用云端版本 / 使用本机版本」让用户选择，并展示两边差异最大的 3 张牌。

### 3.8 界面上的区分

- **账号徽章 `AccountBadge`**：显示在顶部和「我的」页面。
  - B站用户：圆形 B站头像（未授权时用月相头像）+ 昵称 + 一个粉色小角标「B站」。B站粉 `#FB7299` 只用在这个角标上。
  - 匿名用户：月相头像 + 「旅人·A3F9」+ 灰色标签「匿名 · 本设备」。
- 在 Toy 中**未登录**的用户：Box 页顶部显示一条可关闭的提示「登录 B站 后可跨设备同步 Box」（SDK 不提供拉起登录的能力，所以只做提示，不放按钮）。
- 两类用户的「我的」页面都提供 Box 字母码导出 / 导入，用于迁移收藏数据；匿名用户提示数据仅保存在本设备。
- B站用户在匹配详情里点击「开始交换」时，会先检查是否已关注 UP主（见 5.5）；匿名用户没有这一步。
- **匹配对象看到的信息与账号类型无关**：只显示对方的原神 UID、服务器、信用等级，以及对方留言（如果有）。v1 不向对方展示 B站昵称或头像：一方面它们无法被后端校验，另一方面这样能减少隐私顾虑。

### 3.9 部署差异

| 项目 | Toy 包 | Web 包（Vercel） |
|---|---|---|
| 构建命令 | `vite build --mode toy` | `vite build --mode web` |
| `<head>` 中的 SDK | 注入 `<script src="//s1.hdslb.com/bfs/seed/toy/app/sdk/toy-sdk.js">` | 不注入 |
| 资源路径 | 相对路径（`base: './'`），适配 `/toy/<slug>/` 子路径 | 根路径 `/` |
| 外部资源 | 全部打包进项目（字体子集等），不依赖 Google Fonts 或第三方 CDN；平台对包大小和 wasm 没有限制 | 同左（两种包保持一致，便于维护） |
| Service Worker / PWA | 开启（平台已确认允许） | 开启 |
| Web Push 通知 | 首版使用「回到页面时提示」+ 交换标签上的角标 | 同左；Web Push 延后 |
| API 地址 | CloudBase HTTP 网关的 `/api/v1`。平台已确认部署在 B站时请求外部 API 没有跨域问题；网关 CORS 同时允许实际 Toy 页面来源和独立站域名 | 同一个 API；**不能使用任何 B站 能力** |

```

   │   ① ⚡ 快速交换               ——「只选几张，马上开换」
   │   ② 🂠 整理完整 Box           ——「记录全部 22 种，长期使用」
   ▼
[步骤 3/3 · 确认交换内容]  「我能给出」和「我想要」两行卡牌

                     └► 进入等待 → 显示「星轨等待」状态
```

- 3 个步骤顶部有进度条（三颗小月亮依次点亮）。
- 任何一步都可以返回，填过的内容不会丢失（实时保存在本地）。

**两类用户在首次使用时的差异**（主流程完全相同，只有下面几处不同）：

| 节点 | B站用户（Toy 中已登录） | 匿名用户 |
|---|---|---|
| 进入页面 | 后台静默读取云存储，建立或恢复身份（没有弹窗）。如果是老用户，**直接跳到 `#/box`**，即使换了设备也一样 | 只读取 localStorage |
| 引导页 | 主按钮下方有一个次级入口「用 B站头像昵称」，点击后才弹出平台授权窗；不点也不影响使用 | 主按钮下方显示「匿名使用，数据保存在本设备」 |

| 发布页的留言 | 「给对方的留言（可选）」保留原有中文短语，并新增固定时段标签，单选且可取消 | 相同，不提供自由文本输入 |
| Toy 中未登录 | — | 和匿名用户相同，另外显示一条「登录 B站 可跨设备同步」提示 |

### 5.3 加好友（双方都可以主动）

- **不区分发起方和等待方**。双方点击「开始交换」看到完整 UID 后，谁先看到谁先加；如果已经收到对方的好友申请，直接通过即可。
- 页面提示（双方相同）：「在游戏中添加 UID **812345678** 为好友，或留意对方发来的申请。在好友申请里附上下面的留言，对方一看就知道是来换牌的。」
- 提供两个按钮：[复制 UID] 和 [复制申请留言]。
- **申请留言**从复制者自己的视角生成，只描述交换内容，不带任何站点名称：
  - 一对：`换月谕圣牌：我给你「星」，换你的「塔」`
  - 多对：`换月谕圣牌：我给你「星」「月亮」，换你的「塔」「太阳」`
  - 英文：`Lunar Arcanum trade: my The Star for your The Tower`
- **对方状态提示**：对方点击「开始交换」后，你的匹配详情会显示「对方已开始交换，可能很快会加你」。这样双方都知道对方是活跃的，不需要约定谁加谁。

### 5.4 UID 脱敏规则

**原则：交换之前，任何 UID 都是脱敏的；只有在用户点击「开始交换」之后，才显示对方的完整 UID。**

| 场景 | 显示方式 |
|---|---|
| 自己的 UID（「我的」页面、账号卡片） | 默认脱敏 `812****78`，点 👁 临时显示完整 UID，3 秒后自动恢复脱敏；只有在输入框里编辑时才显示完整 UID |
| 匹配之前（等待中） | 不显示任何其他人的 UID |
| 已匹配，还没点「开始交换」 | 对方 UID 脱敏 |
| 点击「开始交换」之后，到匹配结束之前 | 对方的完整 UID + 复制按钮 |
| 匹配结束后（完成、失败、过期） | 回到脱敏状态，历史记录中也一律脱敏 |
| Toast、通知、事件、分享内容 | 一律脱敏 |

- **脱敏格式**：保留前 3 位和后 2 位，中间用 `*` 代替。9 位 UID 显示为 `812****78`，10 位显示为 `181*****45`。前 3 位已经能体现服务器，所以不影响用户辨认。
- **由后端强制执行**：用户调用 `POST /matches/:id/reveal` 之前，`/state` 中的匹配只返回 `uidMasked`，前端无法拿到完整 UID（见 [后端概要设计](cloudbase-backend-design.md)）。
- 「开始交换」（reveal）是不可撤销的动作，后端会记录时间。它的作用有三个：
  1. 让对方看到「对方已开始交换」；
  2. 作为判断「对方没有回应」时的依据之一；
  3. 用于统计双方查看 UID 后的完成率。

### 5.5 查看 UID 前关注 UP主（仅 B站用户）

```
点击「开始交换」
  ├─ 匿名用户（包括 Toy 中未登录的用户）→ 直接显示 UID
  └─ B站用户 → toy.getAuthorRelation()
        ├─ 已关注（isFollowing = true）→ 显示 UID
        ├─ 未关注 → 弹出关注引导抽屉（FollowGateSheet）
        │     ├─ [去关注 UP主] → toy.navigate({ type: 'space', id: authorMid })
        │     │     用户返回页面时（visibilitychange）自动再查一次 → 已关注就自动显示 UID
        │     └─ [我已关注] → 手动再查一次；仍然未关注时提示「好像还没关注成功，再试一次？」
        └─ 调用失败、unsupported、限流 → 不拦截，直接显示 UID
```

```
┌────────────────────────────┐
│          ▁▁▁                │
│   (UP主头像)  UP主昵称        │  ← getAuthorProfile
│              1.2万 粉丝      │
│                            │
│  关注 UP主 后即可查看对方 UID   │
│  本工具免费使用，关注是对作者    │
│  最好的支持 ♡                 │
│                            │
│  ┌──────────────────────┐  │
│  │     去关注 UP主  →     │  │  ← 主按钮（月金）
│  └──────────────────────┘  │
│        我已关注，继续          │  ← 次级按钮
└────────────────────────────┘
```

- **失败时不拦截**：平台故障不能卡住交换。SDK 文档写明外部手机浏览器会返回 `unsupported`，这种情况同样放行。
- `authorMid`（UP主 的 mid）由后端 `/config` 下发，因为 `navigate` 需要传入这个 id。
- 关注检查只在客户端进行，可以被绕过。它只是引导，不是安全措施，所以后端不需要校验。
- 检查结果只在当前会话内缓存。已关注的用户在同一次访问中再次点击「开始交换」时，不再重复调用。

## 6. 页面概要设计

> 本节仅保留页面职责与关键交互规则的概要；详细的视觉线框与组件实现已由静态页面完成，见 `src/partials/*.html` 与对应样式。

### 6.1 引导页 `#/welcome`

展示标题、三步说明（填 UID → 选牌 → 匹配）与「开始交换」入口。已填过 UID（或 B站用户可从云端恢复身份）的用户直接跳到 `#/box`，不再显示引导页。B站用户可选择用头像昵称登录（`getUserProfile`，用户拒绝授权时静默隐藏入口）；匿名用户会看到「数据存在本设备」的提示。

### 6.2 UID 输入（引导步骤 1，也用在设置页）

数字输入框（`inputmode="numeric"`）根据 UID 自动识别所属服务器并展示对应徽章；识别失败时提示「UID 格式不正确」。隐私说明：匹配成功并点击「开始交换」前，UID 不会展示给任何人。

### 6.3 我的 Box `#/box`（核心页面）

顶部分段切换**快速交换 | 完整 Box**，会记住上次选择；两种模式的选牌各自独立保存，互不覆盖。

- **完整 Box 模式**：22 格卡牌网格，顶部展示月相收藏进度（N/22）与缺少/可换统计。卡牌有四种状态——缺少、持有 1 张、可换（≥2 张，带 `+N` 角标）、已锁定（被进行中的匹配占用，不可修改）。点击卡牌打开底部抽屉编辑持有数量与「想要」标记；也可开启批量编辑模式直接在格子下步进加减。修改实时保存到本地，有换牌需求时提示「Box 已改动，更新换牌需求」。
- **快速交换模式**：面向不维护完整 Box 的用户，用两段式选择器分别勾选「我能给出」「我想要」的卡牌，同一张牌不能同时出现在两组中。
- **发布确认**：点击「帮我找人换牌」后弹出确认抽屉，保留中文快捷留言：「今晚 20 点后在线」「随时可加」「工作日晚上」「周末全天在线」。在其下新增方便换牌的固定时间段：08:00–12:00、12:00–14:00、14:00–18:00、18:00–20:00、20:00–24:00、00:00–08:00。留言或时段任选一项，再次点击可取消，不选也可发布。B站与匿名账号均不支持自定义文本，发布与编辑接口统一校验预设白名单；对方按自己的界面语言显示。留言仅在匹配成功后对对方可见，历史自由文本不再展示。

### 6.4 导入截图（v1 不做）

v1 支持手动录入和 Box 字母码导入，不提供截图识别导入（完整 Box 的批量编辑模式已经能较快完成）。截图识别有单独的详细要求，后续单独设计，见第 10 节。界面上不保留截图识别入口，路由 `#/box/import` 也先不注册。

### 6.5 交换 `#/trade`

页面分三个区块：**我的换牌需求**、**待完成的交换**、**历史记录**。

- 换牌需求等待中会显示分区在线人数、稀缺提示，以及撤回/重新匹配（每天 1 次）入口；独立站支持开启匹配成功通知，Toy 内无推送能力，改为提示下次打开可见。
- 匹配成立后播放约 2.2 秒的揭晓过场动画（可跳过），随后进入匹配详情 `#/trade/:id`。
- 匹配详情分「开始交换」前后两种状态：点击「开始交换」前 UID 保持脱敏；点击后（B站用户先做关注检查，见 5.5）以逐位「解码」效果显示完整 UID，并给出好友申请留言的复制入口。确认期限 48 小时，从匹配成立起算，不因点击「开始交换」而重置。
- **交换完成**：支持按对勾选完成情况，确认后 Box 数量自动更新（可撤销）；集齐 22/22 时播放满月动画。
- **遇到问题**：提供单选原因（对方未加好友/未回应/没有牌/不想换/我自己无法完成/其他），原因决定处罚对象与重新匹配逻辑（见 11.4），用户只看到结果说明，不感知具体判定细节。
- 历史记录以列表展示：日期、对方脱敏 UID、交换内容缩略、状态标签。

### 6.6 我的 `#/me`

顶部为账号卡片，两类用户显示不同：B站用户展示头像/昵称/云同步状态（已同步/同步中/同步失败/有冲突）与「关注 UP主」入口；匿名用户提示数据保存在本设备。下方是共用的设置项（语言、特效、保留张数等）与数据管理能力（Box 字母码导出 / 导入、PC 端扫码继续、清除本地数据等）。修改 UID 时若有已发布的换牌需求或待完成的交换会二次确认将撤回换牌需求；UID 默认脱敏，可临时查看（见 5.4）。

Box 字母码无前缀，按位打包（含 2 位版本号）并经 CRC-10 校验，转为 32 字符无歧义字母数字串。数量按实际最大值选择位宽，保留 22 种牌的准确张数（0–9）、保留数、想要标记、快速交换选牌和当前模式。粘贴时自动识别有效字母码，一键替换本机 Box；有进行中的交换时禁止导入，避免破坏已锁定的数量。字母码不迁移账号或交换记录，格式详见 [Box 字母码格式](box-code.md)。

### 6.7 通用组件与异常状态

页面间复用的组件（卡牌格/大卡、步进器、底部抽屉、徽章、Toast、空状态、同步指示、Box 字母码输入等）已在静态实现中落地，不再逐一列出规格。关键的空/错误/加载态处理原则：Box 为空或已集齐时给出明确的空状态与引导操作；网络断开或接口出错时不清空用户输入，并以 Toast/离线提示 + 自动重试处理；云端数据冲突时提供差异选择；平台能力缺失（SDK 加载失败、不支持某项能力）时静默降级为匿名流程或隐藏对应入口，而非报错。

## 7. 视觉设计规范

### 7.1 风格关键词

**月夜 · 银色拱窗 · 星屑 · 玻璃质感 · 克制的金色**

卡面本身已经是高饱和、色彩丰富的插画，所以界面 UI 保持**深色、低饱和**，把视觉焦点让给卡面。银色拱窗边框是素材的统一元素，UI 的卡片容器顶部圆角用拱形来呼应。

### 7.2 色彩 Token

```css
:root {
  /* 背景层级 */
  --bg-0: #070914;          /* 最底层夜空 */
  --bg-1: #0D1124;          /* 页面背景 */
  --surface-1: rgba(28, 34, 66, .62);   /* 玻璃卡片 */
  --surface-2: rgba(44, 52, 96, .72);   /* 抽屉 / 浮层 */
  --border: rgba(214, 222, 240, .14);

  /* 文字 */
  --text-1: #EEF1F8;
  --text-2: #A9B1C9;
  --text-3: #6B7391;

  /* 品牌 */
  --moon-silver: #D6DEF0;   /* 主强调：边框、图标 */
  --moon-gold:   #E9C77B;   /* 主按钮、可换角标、匹配成功 */
  --arcane:      #9C8CFF;   /* 次强调：选中、链接 */
  --glow-cyan:   #7FD8FF;   /* 星光、扫描线 */

  /* 语义 */
  --ok:   #5ED6A0;
  --warn: #F2B35B;          /* 待确认 */
  --bad:  #E36D7A;

  /* 卡牌主色：由 JS 按卡牌注入 */
  --card-color: #4D6FBF;
}
```

- 只做**深色主题**，不做浅色主题，因为月夜氛围是产品的核心。
- 对比度：正文 `--text-1` 和 `--text-2` 在 `--bg-1` 上的对比度都 ≥ 4.5:1。
- 金色仅用于「主操作」和「好消息」，**每屏最多出现一处大面积金色**。
- B站粉 `--bili-pink: #FB7299` 只用于 `AccountBadge` 上的「B站」小角标，不用于其他地方，避免破坏月夜主色调。

### 7.3 字体

| 用途 | 字体 |
|---|---|
| 中文正文 | 系统字体：`-apple-system, "PingFang SC", "HarmonyOS Sans SC", "MiSans", "Microsoft YaHei", sans-serif`（不加载中文网络字体，节省流量） |
| 英文标题 / 罗马数字 | `Cinzel` 600 字重，**自托管 woff2 子集**（约 20KB）。两种部署包都打包在项目内，不依赖 Google Fonts，因为 Toy 平台可能无法访问外部资源 |
| UID / 数字 | `"JetBrains Mono", ui-monospace, monospace`，或系统等宽字体，用于对齐 |

字号：标题 22 / 18，正文 15，辅助文字 13，卡牌数量 14 粗体。行高 1.5。

### 7.4 卡牌视觉

- 卡牌原图比例为 684×1024（约 2:3），网格中保持原比例，不裁切。
- 原图自带银色拱窗边框，**UI 不再给卡牌加边框**。不同状态通过外发光、角标和透明度来区分。
- 外发光用 `filter: drop-shadow(0 0 12px var(--card-color))`。低特效档改为静态的 `box-shadow` 光晕图层。
- **选中态**：卡牌上浮 4px，外发光加强，底部出现一条主色细线。

### 7.5 背景

- 深蓝径向渐变（顶部偏紫，底部近黑）+ 星空层 + 一个半透明大月亮轮廓（只在引导页和交换页出现）。
- 当前页面焦点卡牌的主色会以 15% 透明度柔和地染到背景上（例如打开「星」的抽屉时，背景微微偏蓝）。

### 7.6 可选素材的使用

| 素材 | 是否必需 | 建议用途 |
|---|---|---|
| `cards/*.png`（22 张） | **必需** | 所有卡牌展示 |
| `numerals/*.png`（22 个数字字形） | 可选 | 可用作大卡详情页的装饰编号；不用时直接显示罗马数字文本（Cinzel 字体） |
| `Item_Lunar_Arcana_Case.png`（圣牌盒） | 可选 | 可用作网站图标、PWA 图标或空状态插画；不用时用 CSS 绘制的月亮图标代替 |

设计不依赖任何可选素材。

### 7.7 布局与间距

- 采用 4px 基准网格；页面左右边距 16px；卡片圆角 16px（拱形容器顶部用 `border-radius: 50% 50% 16px 16px / 24px 24px 16px 16px`）。
- 断点：
  - `<600`：4 列卡牌网格
  - `600–1023`：6 列
  - `≥1024`：8 列 + 侧边栏
- 所有可点击区域 ≥ 44×44px。

## 11. 匹配机制

### 11.1 匹配池

- 匹配池按分区（`region`）隔离。
- 每个交换账号同一时间**最多有 1 条有效换牌需求**；不同账号填写相同 UID 时，各自的需求正常进入匹配池。
- 换牌需求内容：
  - `give`：`{cardId: qty}`，数量来自 Box 的可换数，或快速模式下手动选择的数量
  - `want`：`[cardId]`，每种默认想要 1 张
- 通过 CloudBase PostgreSQL 中的需求、分区和状态索引查询供需，给出的可用数量及想要名额均扣除占用；首版不维护独立 Redis 匹配池。

### 11.2 即时贪心匹配（来一个，配一个）

匹配分为两种角色，**只用于计算上限，不影响加好友的方式**：

- **主动扫描**：用户发布换牌需求或重新匹配时，系统立刻替他扫描匹配池。这一次**最多匹配 3 对**。
- **被动等待**：换牌需求留在池中，被别人的主动扫描匹配到。被匹配的次数和总张数**不限**。

新的换牌需求 A 发布（或重新匹配）时：

```
budget = 3                                   // 本次主动扫描最多 3 对

candidates = 同分区所有满足以下条件的换牌需求 B：
    B 处于等待中，且 B.accountId ≠ A.accountId // 被动方没有并发上限；不按游戏 UID 排除候选
    A、B 的交换账号之间 30 天内没有失败过的交换记录
    X = A.give ∩ B.want   (A 能给 B 的)
    Y = B.give ∩ A.want   (B 能给 A 的)
    k = min(|X|, |Y|, budget)   (按可用数量计)，要求 k ≥ 1

score(B) = 10·k                      // 优先一次换得更多（少加几个好友）
         + Σ rarity(card)            // 优先满足稀缺卡
         + priority(B)               // 信用与等待时长，见 11.5

while budget > 0 且还有候选:
    选 score 最高的 B，生成包含 k 对交换的匹配（每对严格 1 换 1）；
    配对时，在 X 和 Y 中优先把稀缺度高的牌配在一起；
    锁定双方对应的卡牌数量（reserved）；
    budget -= k；按新的 budget 重新计算其余候选的 k 和 score

A 的剩余部分转为被动等待，留在匹配池中。
```

- 因为每个匹配都由一次主动扫描产生，所以**每个匹配最多 3 对**。
- 优先把 3 对集中在同一个人身上（`10·k` 权重最高），这样可以减少需要加的好友数量。
- `rarity(card)` = 该分区内 `demand(card) / (supply(card) + 1)`，每分钟重新计算一次。这个值同时用于前端的「稀缺」提示。
- **为什么用贪心**：用户希望能配就立刻配。完全最优的二部图匹配需要批量计算，会引入等待。因此「即时」优先，用 k 最大和稀缺优先作为局部最优的近似。
- **扩展点**：后续可以增加一个低频（例如每 10 分钟）的批处理，在匹配池里寻找 A→B→C→A 这样的三人环形交换，以提升整体匹配率。v1 不做。

### 11.3 并发与锁

- 同一分区的匹配操作通过 PostgreSQL RPC 内的事务锁串行执行，卡牌占用、匹配创建和次数扣减一起提交；编辑、撤回、结算和超时释放遵守相同的锁顺序。
- 被锁定的卡牌在前端显示「交换中」，不能修改，也不能参与其他匹配。占用以账号及其需求为单位，相同 UID 的其他账号不共享库存或占用。

### 11.4 失败处理（匹配上了但没换成）

匹配有效期为 **48 小时**。根据双方的确认结果处理：

| 情况 | 匹配结果 | 发起报告者 | 对方 | 卡牌 |
|---|---|---|---|---|
| 双方都确认完成 | 完成 | 信用 +2 | 信用 +2 | 扣除锁定的数量（前端提示更新 Box） |
| 一方确认完成，对方超时未操作 | 视为完成 | +2 | 不变（提醒对方确认） | 同上 |
| A 报告「对方没加 / 没回应 / 没牌 / 不想换了」 | 失败 | 不扣分，**自动回到匹配池，不消耗今日次数**，排序优先 | 信用 −15（「没牌」或「不想换了」为 −10） | 释放 |
| A 报告「我自己没办法完成」 | 失败 | 信用 −5 | 自动回到匹配池，排序优先 | 释放 |
| 双方都超时未操作 | 过期 | 双方各 −5 | — | 释放，换牌需求回到匹配池 |
| 双方说法矛盾（一方说完成、一方说失败） | 争议 | 都不扣分，记录争议次数；争议 ≥ 3 次的账号进入人工复核 | — | 按失败处理 |

- 被报告的一方会收到通知，并可以在 24 小时内**申诉**，提交「我已完成」或补充说明，申诉后按「争议」处理。
- 失败过的两个交换账号，30 天内不会再被互相匹配；不影响填写相同 UID 的其他账号。

### 11.5 信用与优先级

- 信用分按交换账号记录，初始为 100，上限 150，不对用户公开具体数字，只显示为 5 颗月亮；填写相同 UID 的账号各自计算信用、失败次数与冷却。
- `priority = credit_factor × (1 + min(等待小时数, 72) / 24)`

| 信用分 | 状态 | `credit_factor` |
|---|---|---|
| ≥ 90 | 良好 | 1.0 |
| 60–89 | 一般 | 0.6 |
| 30–59 | 较低 | 0.3，并且只能作为被动方等待匹配 |
| < 30 | 冷却 | 移出匹配池 7 天，到期后信用重置为 50 |

- **连续失败 3 次**（作为责任方）→ 直接进入冷却。
- 信用分每完成一次交换 +2，每 7 天无不良记录自然恢复 +5（最高到 100）。

### 11.6 限频

| 行为 | 限制 |
|---|---|
| 主动发布或**重新匹配** | 每个交换账号每天 1 次，按其 UID 所属**服务器的 04:00** 刷新，与游戏日一致：国服、亚服、港澳台服为 UTC+8，美服为 UTC−5，欧服为 UTC+1；相同 UID 的不同账号独立计数，修改 UID 不清空已用次数 |
| 因对方原因失败后自动回池 | 不计次数 |
| 等待期间编辑换牌需求 | 不限次数，但编辑后**不会触发主动扫描**，只能等待别人来匹配，防止通过编辑来刷匹配 |
| 撤回换牌需求 | 不限次数；撤回后当天再次发布会消耗次数 |

### 11.7 反作弊（v1 轻量处理，不作为重点）

- 限流：每个设备和 IP 的写操作 ≤ 30 次 / 小时；不按原神 UID 共享每日匹配额度或设置占用限制。
- UID 格式校验（见 2.5），拦截明显无效的 UID。
- UID 允许重复填写，不校验账号间的 UID 唯一性，不产生重复提示、标记或额外操作，按普通需求匹配。
- 数据异常（例如单张牌数量 > 99，或给出总数 > 200）→ 拒绝请求。
- 提供举报入口（「对方 UID 是假的」等），举报关联具体匹配和对方交换账号；被多人举报的账号进入人工复核，不连带处理其他同 UID 账号。
- **账号类型不能作为信任依据**：后端无法验证「这个人确实是 B站用户」（见 3.2），所以所有风控规则都以交换账号、设备和 IP 为准，对两类账号一视同仁。
- **留言的二次过滤**：客户端的 `checkInputSafety` 可以被绕过，所以后端对留言再做一次长度限制（≤40 字）和基础敏感词过滤；去除链接、QQ 号、手机号等联系方式，防止引流。被举报的留言会被隐藏。
- **UID 泄露防护**：完整 UID 只通过 `reveal` 接口返回，并且只返回给匹配双方。reveal 次数异常（例如短时间内大量匹配后立即 reveal 再撤单）的账号进入人工复核，防止有人利用匹配来收集 UID。

### 12.3 图片资源处理

原始卡图为 684×1024 PNG，每张约 700KB，22 张共约 15MB，不能直接在页面使用。用构建脚本（`sharp`）生成以下尺寸：

| 尺寸 | 用途 | 格式 | 预计大小 |
|---|---|---|---|
| 160w | 网格 `CardTile` | WebP（q80）+ AVIF | ~10–15KB |
| 360w | 抽屉 `CardLarge` | WebP | ~35KB |
| 684w | 匹配揭晓 / 高 DPR 大卡 | WebP | ~90KB |
| 48w | `CardChip` | WebP | ~3KB |

- 使用 `<img srcset>` 和 `loading="lazy"`；网格首屏的 8 张图片设置为 eager 加载。
- 两种包都由 Service Worker 预缓存 160w 那一套（约 300KB）。
- 平台对 Toy 包大小没有限制，但为了加载速度，两种包都只打包上表中的 4 套 WebP 尺寸，不打包原始 PNG。

### 12.4 前端状态与同步

- **Box 的主数据保存在本地 localStorage**，发布换牌需求时才把 give / want 提交到后端；后端不保存完整 Box。
- B站用户由 `cloud-sync.js` 负责与云存储双向同步（键规划见 3.7）：
  - 启动时读取一次云存储。
  - 编辑后防抖 5 秒写入。
  - 页面切到后台时立即写入。
- 身份：
  - B站用户按 3.3 的流程，进入页面时静默建立身份。
  - 匿名用户按 3.4 的流程，首次发布时才建立身份。
  - CloudBase 会话由 SDK 持久化和续期，不再自行保存 `las.token`。
- 匹配状态更新：
  - 页面可见时，每 15 秒轮询 `GET /state`，一起获取身份、需求、匹配、额度和汇总统计，不受 Toy 云存储的限频约束。
  - 页面切到后台时停止轮询，切回前台时立即拉取一次。
  - 首版统一在页面内提示，Web Push 延后，不建设独立事件流。
  - v1 不使用 WebSocket，保持后端简单。

### 12.5 平台适配层

业务代码只依赖下面这个统一接口。Toy 环境和独立站各自提供实现，不支持的能力返回 `null` 或 `false`，界面据此决定是否显示对应入口：

```js
// src/platform/index.js 导出
platform = {
  env,                         // 'toy-app' | 'toy-web' | 'standalone'
  can(feature),                // 'share' | 'saveImage' | 'qrcode' | 'cloud' | 'profile'
                               // | 'inputSafety' | 'follow' | 'container'（结果在启动时缓存）
  cloud: { get(keys), set(items), remove(keys) } | null,
  getProfile(),                // → { avatar, nickname, toyOpenId? } | null；必须在用户手势中调用
  checkText(text, scene),      // → 'ok' | 'rejected' | 'unavailable'；不支持时返回 'unavailable'
  share({ path, title }),      // toy.share → navigator.share → 复制链接
  saveImage({ dataUrl, name }),// toy.saveImageToAlbum → <a download>
  qrcode({ path }),            // toy.getQrCode → 包内二维码库（独立站）
  onSafeArea(cb),              // toy.onContainerChange → env(safe-area-inset-*)
  author: {
    isFollowing(),             // getAuthorRelation → true | false | null（null 表示无法判断，放行）
    profile(),                 // getAuthorProfile → { avatar, nickname, follower } | null
    openSpace(),               // toy.navigate({ type: 'space', id: authorMid }) → 外链；必须在用户手势中调用
  },
}
```

- **环境检测**：
  1. 构建变量 `VITE_TARGET`（`toy` 或 `web`）决定是否注入 SDK。
  2. 运行时再检查 `window.toy` 是否存在：Toy 包里 SDK 加载失败时自动降级为 `standalone`，并按匿名用户处理。
  3. `toy-app` 和 `toy-web` 的区分：用 `await toy.isSupport('closeBrowser')` 判断。
- **错误统一处理**：SDK 抛出的错误都带 `[ToySDK]` 前缀。适配层把它们转成 `PlatformError { kind: 'unsupported' | 'rate_limited' | 'not_logged_in' | 'invalid' | 'unknown' }`，其中 `307044` 对应 `rate_limited`。
- **退避重试**：`rate_limited` 时按指数退避自动重试（见 3.6），业务层不需要关心。

## 13. 后端接口概要

接口清单和架构以 [CloudBase 后端概要设计](cloudbase-backend-design.md) 为准，共 11 个接口，采用 REST + JSON，前缀 `/api/v1`。

### 13.1 接口收敛

- `GET /state` 合并身份、当前需求、匹配列表与详情、额度及汇总统计；历史分页返回，当前需求不存在时返回 `null`。
- `GET /config` 只下发当前部署的公开登录参数及 UP 主 MID；服务器、UID 规则、留言等静态数据随前端打包。UID 解析复用前后端规则，绑定时由后端再次校验。
- 保留发布、编辑、撤回、重新匹配、开始交换和结果确认这些有独立业务语义的操作。
- 申诉与举报合并为 `POST /matches/:id/feedback`，B站资料去重并入 `PUT /me`。
- 每 15 秒轮询状态，替代事件接口；Web Push 订阅延后。

### 13.2 鉴权与约束

匿名用户使用 CloudBase SDK 匿名登录；B站用户通过 `/session` 将账号密钥换成自定义登录 Ticket，再由 SDK 建立会话。业务接口验证 CloudBase 访问令牌，不自建会话表或续期接口。不提供「只用 toyOpenId 登录」的接口，原因见 3.3。

UID 只校验格式并识别服务器，允许不同账号重复填写，保存与匹配均不返回重复状态；有本人账号的有效需求或未结束匹配时不允许修改 UID。需求归属和匹配访问按账号 ID 校验，不能通过相同 UID 访问其他账号的数据。完整 UID 仅向已开始交换的参与者展示，匹配结束后不再下发。匿名用户不能提交自由文本留言，服务端仍对所有留言执行过滤。

### 13.3 统一错误格式

```json
{ "error": { "code": "DAILY_LIMIT", "message": "今日重新匹配次数已用完", "retryAt": "2026-11-14T04:00:00+08:00" }, "requestId": "…" }
```

常见错误码：`UID_INVALID`、`DAILY_LIMIT`、`COOLDOWN`、`LISTING_EXISTS`、`CARDS_LOCKED`、`RATE_LIMITED`、`CREDENTIAL_INVALID`、`BILI_ALREADY_LINKED`、`NOTE_TEXT_FORBIDDEN`、`NOTE_REJECTED`。原神 UID 重复正常成功，不返回冲突错误。

## 14. 数据模型概要

```
Account    (id, authUserId UNIQUE, type[anon|bili], credentialHash?, -- bili：云存储中的密钥，仅存哈希
            toyOpenIdHmac? UNIQUE,                          -- bili：授权后才有，只用于去重
            createdAt)
Player     (accountId PK, uid?, server, region, credit, completedCount, failStreak,
            cooldownUntil?, dailyQuotaUsedAt?, createdAt)  -- 信用跟随交换账号，与账号类型无关；原神 UID 可重复
Listing    (id, accountId, uidSnapshot, region, give JSON{id:qty}, want int[], reservedGive JSON{id:qty}, reservedWant int[],
            mode, note JSON{preset|text}?, status[waiting|closed], version, createdAt, updatedAt)
Match      (id, region, accountIdA, accountIdB, uidSnapshotA, uidSnapshotB, listingA, listingB, scannedBy, -- scannedBy：哪一方账号的主动扫描产生了这个匹配（用于计算 3 对上限）
            pairs JSON[{aGives, bGives}], revealedAtA?, revealedAtB?,
            status[matched|confirming|completed|failed|expired|disputed],
            confirmA JSON?, confirmB JSON?, expiresAt, createdAt)
PairBlock  (accountIdA, accountIdB, until)                 -- 失败过的两人互相屏蔽，按交换账号记录
Feedback   (id, reporterAccountId, targetAccountId, matchId, kind[appeal|report], reason, note, status, createdAt)
RequestRecord (id, accountId?, idempotencyKey?, requestHash?, result?, deviceHash?, ipHash?, createdAt, expiresAt)
```

使用 CloudBase PostgreSQL 持久化业务数据，内部 RPC 执行事务和占用控制；短期请求记录用于幂等与限频。不保存 Session 和 Event，分别由 CloudBase Auth 与状态轮询替代。云函数使用 Node.js，首版由一个 HTTP 函数和一个定时事件函数组成。

所有权、关联外键及业务额度以账号 ID 为依据。`Player.uid` 是可重复的游戏信息，不设唯一约束；换牌需求与匹配保留 UID 快照，用于服务器识别、脱敏和开始交换后的展示。

隐私要求：

- `toyOpenId` 原文**不落库**，只保存 `HMAC(serverSecret, toyOpenId)`。
- 请求日志中过滤 `toyOpenId`、`credential`、`ticket`、`token` 字段和认证请求头。
- B站昵称和头像不上传后端（只在本机展示）。
