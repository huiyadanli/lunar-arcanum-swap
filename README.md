# lunar-arcanum-swap

**更好的原神 · 月谕圣牌交换站**，隶属于 [BetterGI](https://github.com/babalae/better-genshin-impact) 项目。原神「月谕圣牌」交换站。设计文档见 [docs/design.md](docs/design.md)，后端方案见 [CloudBase 后端概要设计](docs/cloudbase-backend-design.md)（21 个接口精简为 11 个，已部署并提供前端接入模式）。

米游社图片导入 Box 已接入，见[当前设计与实现说明](docs/miyoushe-box-import-flexible.md)。采用浏览器本地颜色分割与自适应牌框定位，不依赖固定分辨率、宽高比或页首页尾模板，仅保留493字节的数字“2”特征。实际JavaScript核心已通过三张原图及缩放、裁边、留边、行距变化等36个回归用例。

## 后端开发

CloudBase 后端和 PostgreSQL 数据库已部署，包含 11 个接口、匹配事务和每分钟定时维护；匿名登录、B站身份登录、重复 UID 与真实并发匹配已通过已部署 API 联调。[配置接口](https://lunar-arcanum-swap-d9cl8ad90b4e4-1252025612.ap-shanghai.app.tcloudbase.com/api/v1/config)可访问，运行与发布方式见 [后端说明](backend/README.md)。前端通过 `npm run dev:online` 连接真实线上后端，`npm run dev` 保留原型模拟模式。

在本机已有 `.secrets/backend.runtime.json` 的情况下，运行 `npm run test:backend:online` 即可验证当前线上后端，无需手动输入接口地址或启动本地后端。验证会创建测试身份并写入云数据库，结束后撤回测试身份的等待需求；成功时输出 `"ok": true` 和 `"mode": "deployed-api"`。

## 前端运行

原生 ES Modules + Alpine.js，使用 **Vite 构建为纯静态文件**。Alpine.js 保留在 `src/vendor/`，构建时一起打包，不依赖 CDN。
默认运行使用模拟后端和模拟 B站 Toy SDK（`src/mock/`）；online 模式使用真实 CloudBase 登录和线上业务 API，不注入模拟 Toy SDK。

### 运行

开发和构建需要 Node.js 20.19+（20.x）或 22.12+，以及 npm。

```bash
npm install
npm run dev
# 打开终端显示的本地地址，默认 http://localhost:5173/
```

### 本地前端连接真实线上后端

```powershell
npm run dev:online
# 打开终端显示的地址，默认 http://127.0.0.1:5173/
```

此命令持续运行本地前端，页面里的 UID 保存、发布、编辑、撤回、匹配、查看 UID 和确认结果均请求真实线上 API。无需启动本地后端，也无需 `.secrets/backend.runtime.json`；前端从公开 `/config` 获取登录配置，由 CloudBase Web SDK 建立和续期匿名会话。浏览器状态与模拟模式隔离，线上接口失败时直接提示错误。

双人测试可以使用普通浏览器窗口和无痕窗口（或两个不同浏览器），分别填写同一服务器的 UID。一方给出 A、想要 B，另一方给出 B、想要 A；发布后应能真实匹配。有进行中交换时每 10 秒刷新，仅等待匹配时每 30 秒刷新，没有需求和进行中交换时停止持续轮询，若仍在发布冷却则只安排到期刷新；切回页面和完成操作后获取完整状态。轮询省略历史与供需统计，交换结束后自动补拉最终记录。两份无痕窗口通常共享同一会话，请使用彼此隔离的浏览器环境。

online 模式隐藏模拟调试按钮，按真实发布 / 重新匹配冷却运行（B站授权用户 1 分钟，匿名用户 20 分钟；匹配不要求 B站授权）；操作会写入线上数据库，测试结束可撤回等待中的需求。完整 Box 仍保存在当前浏览器，真实 Toy 环境按原有逻辑同步到 Toy 云存储。B站真机来源还需要配置安全域名和 UP主 MID；本地使用匿名身份即可测试交换流程。

公开 API 地址配置在 `.env.online`。需要连接其他后端时，在已忽略的 `.env.online.local` 中设置 `VITE_API_BASE_URL`，重新启动开发服务；不要向前端配置写入服务端 API Key 或签票私钥。

### 构建与部署

```bash
npm run build
npm run preview
# 本地预览构建结果，默认 http://localhost:4173/
```

需要构建连接真实 API 的版本时，执行 `npm run build:online`；随后可用 `npm run preview` 预览。

同一份线上构建可用于 B站 Toy 和独立站：页面仅在 `bilibili.com`、`bilibilitoy.com` 或其子域名下自动加载真实 Toy SDK，并等待加载后再识别 App / Web 能力；其他域名不加载、不启用真实 Toy SDK。加载失败或超过 10 秒时记录控制台警告，继续使用独立站能力。本地默认模拟模式仍支持 `?mock=bili` 等显式模拟参数，B站域名下不会注入模拟 SDK。

构建产物在 `dist/`，包含 `index.html` 和带内容哈希的 JS、CSS、卡图、字体。
HTML 页面片段通过 `?raw` 在构建时打包，不再在运行时请求 `src/partials/`。
只需将 **`dist/` 的全部内容**上传到任意静态托管服务，部署环境不需要 Node.js 或 Python。

Vite 配置使用 `base: './'`，同一份产物支持域名根目录和子目录部署（例如 `/lunar-arcanum-swap/`）。
页面继续使用 `#/box` 这类 Hash 路由，不需要服务器配置路由回退。
开发服务器和 `vite preview` 仅用于本地开发、检查；部署时直接托管 `dist/`。
构建产物仍需通过 HTTP(S) 访问，不能用 `file://` 双击打开。

CI 中可使用 `npm ci` 安装锁定版本，然后执行 `npm run build`；静态托管平台的构建命令为 `npm run build`，输出目录为 `dist`。

### 切换两类用户 / 运行环境

以下调试参数和面板用于默认模拟模式；online 模式在本地按匿名用户运行，不模拟 B站登录和匹配。

| 地址 | 效果 |
|---|---|
| `/?mock=anon` | 独立站（如 Vercel）上的**匿名用户** |
| `/?mock=bili` | B站 App 内的 **B站用户**（`toy-app`，顶部有模拟的 App 容器栏） |
| `/?env=toy-web` | B站 网页端打开 Toy（无分享 / 相册 / 容器能力） |

选择会记住。页面左边缘（PC 在右边缘）有一个扳手图标的调试把手，可以：

- 切换运行环境、B站 登录状态、是否已关注 UP主；
- 设置发布时「立即匹配」为随机 / 总是 / 从不；
- 模拟对方的行为：有人匹配到我、对方开始交换、对方确认完成；
- 清除发布冷却、清空全部数据。

### 原型覆盖的设计点

- 引导 3 步（UID 实时识别服务器 → 选择快速 / 完整 Box → 选牌发布）
- 完整 Box：月相进度、筛选、卡牌抽屉（倾斜光泽、长按连续加减、左右滑动切换）、批量编辑
- 快速交换：给出 / 想要两组，点击 +1，长按移除，互斥提示
- 发布确认：B站用户写自由留言（模拟 `checkInputSafety`），匿名用户选预设短语；发布后直接进入交换页
- 匹配：主动扫描最多 3 对、揭晓动画、UID 全程脱敏 →「开始交换」才显示（解码动画）→ B站用户需先关注 UP主
- 完成 / 遇到问题的确认流程，完成后 Box 自动更新（可撤销）
- 我的：两类用户的账号卡片、云同步状态、Box 字母码导出 / 导入、语言 / 特效 / 保留张数
- 特效仅提供开 / 关两种设置；开启时内部自动检测画质（华丽 / 流畅），运行中持续掉帧会自动降档；中英双语

### 交换名片

在「我的 Box」的快速交换或完整 Box 中，选好「给出」和「想要」两组卡牌后，即可点击「制作交换名片」。从 Box 生成名片时使用完整选牌，已选中但正在交换的卡牌仍会计入，不按撮合时的可用牌过滤。已发布的需求也能在「交换 → 我的换牌需求」生成名片。名片使用对应入口的需求快照，完整展示卡面、名称、可换数量、服务器、生成日期及站点二维码。默认展示完整 UID，可在预览中主动隐藏。预览即保存的 1080px 宽 JPG 压缩图片，牌多时自动增加高度；编码质量会按体积适度调整，目标为 600 KB 左右以内，界面显示实际大小。B站 App 内保存到相册，其他环境下载图片；手机也可长按预览保存。

- **自部署**：本地生成二维码，使用当前站点目录（兼容子目录），去掉调试参数。可通过 `VITE_PUBLIC_SITE_URL` 固定对外地址。
- **B站 Toy（包括未登录用户）**：优先调用 `toy.getQrCode`，图片上的地址使用同一次 SDK 返回的实际链接，并标注使用 B站 App 扫码。SDK 不可用时，只回退到当前真实的 B站 Toy 地址或 `VITE_BILIBILI_TOY_URL`；不会混用自部署地址。
- **本地模拟 Toy**：先复制 `.env.example` 为 `.env.local`，填写实际发布的 `VITE_BILIBILI_TOY_URL`，再启动开发服务。没有真实地址时会提示无法生成，不使用占位地址或装饰性假二维码。模拟 App 的保存操作实际下载图片，方便检查结果。

上述 `VITE_*` 值在构建时写入产物，正式部署修改配置后需要重新构建。二维码只包含站点入口，不包含 UID 或登录凭据。

### 从米游社图片导入 Box

在「我的 Box → 从图片导入 Box」或「我的 → 从图片导入 Box」选择图片，也可在字母码导入抽屉切换。图片仅在浏览器本地处理，不上传、不识别或修改图片中的UID。

- 自动识别0 / 1 / 2张，展示22张牌的当前数量与导入数量。可逐张修改为0–99，并查看对应原图局部；未确认项可手动填写或明确保留当前数量。
- 可展开「调整识别区域或牌序」，在原图上框选牌区、指定列数和首行最左侧牌后重新识别；局部漏框不会清空其余识别结果。
- 点击「导入并替换 Box」才写入数量，并切换为完整模式；保留用户设置的保留张数、想要开关与身份信息，快速选牌按新 Box 重建（给出数量上限为 9）。重复导入不会相加。
- 识别期间可以停止、重新选图或关闭抽屉；过期任务不会覆盖新草稿。有进行中的交换时禁止应用，已有换牌需求需手动更新。

算法与字形数据仅在选图时加载，无新增npm运行时依赖。重新选图或关闭抽屉时释放图片与Object URL，原始图片不会进入本地状态或B站云同步。

`npm test` 包含数量提交、取消、牌位校准等检查；本机有 `docs/assets/mine.jpeg`、`2.jpg`、`3.png` 和Python + Pillow时，也会自动执行36个真实图片与变体的JavaScript回归。Python仅用于测试时解码样图，网页不依赖Python。内置浏览器连接不可用，本次未完成页面和真机实测。

### 圣牌 Box 字母码

在「我的 → 导出圣牌 Box」复制字母码，再到「导入圣牌 Box」粘贴。界面自动识别并校验，点击「导入并替换 Box」即可应用。字母码包含 22 种圣牌的准确张数（每种 0–9）、保留张数、想要标记、快速交换选牌和当前模式，不包含身份凭据或交换记录。已有进行中的交换时暂不允许导入；已有等待中的换牌需求可在导入后手动更新。

数据按位打包，数量根据实际最大值选择位宽，0/1 收藏状态每张牌只占一位；含 2 位版本号，快速交换数据、“不想要”标记为空时整块省略，末尾加入 CRC-10 校验后转为 32 字符的无歧义字母数字串（无前缀，去掉 0/O/1/I）。完整格式见 [Box 字母码格式](docs/box-code.md)。

### 目录

```
index.html              页面骨架
vite.config.js          Vite 构建配置（相对资源路径）
package.json            开发 / 构建 / 预览命令
src/main.js             Alpine 组件：状态、路由、业务流程
src/partials/*.html     各页面与抽屉的模板（构建时打包）
src/platform/           平台适配层（Toy SDK / 浏览器能力）
src/mock/               模拟后端、模拟 Toy SDK、调试配置
src/fx/                 特效：星空、倾斜、解码、揭晓动画、性能分级
src/styles/             tokens / base / components / pages
assets/cards/           由脚本生成的 WebP 卡图（160 / 360 / 684 宽）
assets/icons/           本地自绘 SVG 图标，替代 emoji 和字符图标
scripts/build-assets.py 从 docs/assets/cards 原图生成 WebP
dist/                   构建产物（不提交 Git）
```

重新生成卡图：`python3 scripts/build-assets.py`（需要 Pillow）。

UI 图标统一引用 `assets/icons/ui.svg`，不需要联网或额外依赖。使用方法见 [图标说明](assets/icons/README.md)。
